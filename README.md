# microlearn

Daily micro-learning lessons for niche professions. Each user gets a small
number of short, vertical, AI-generated lessons dropped into a feed once a
day; watching them extends a streak, and a subscription tier controls how
much of the drop is unlocked.

Nothing here is uploaded by a human. A scheduled pipeline picks a topic
per profession, writes a script with Gemini, narrates it with Gemini TTS,
draws one slide per beat with Gemini's image model, stores the assets in
Supabase, and distributes a delivery row to each subscriber's feed.

A lesson is **narration over slides**, not rendered video — generated
footage costs roughly 20× more per lesson for a format that is mostly a
talking diagram. See
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#why-slides-and-not-generated-video).

## Stack

| Layer | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router, Turbopack, React 19) |
| Language | TypeScript 5.9, `strict` |
| Data | Supabase (Postgres, Auth, Storage, RLS) |
| Background jobs | Inngest |
| AI | `gemini-3.7-flash` (scripts), `gemini-3.1-flash-tts-preview` (narration + word timings), `gemini-3.1-flash-image` (slides) |
| Media | narration `.wav` + slide images, cued from the measured audio length |
| Billing | Stripe |
| Styling | Tailwind CSS 4 |
| Tests | Vitest |

## Quick start

Requires Node 20+, Docker (for the local Supabase stack), and the
[Supabase CLI](https://supabase.com/docs/guides/cli).

```bash
npm install
supabase start                 # starts Postgres, Auth, Storage, Studio
supabase db reset              # applies migrations in supabase/migrations
```

Write the local credentials into `.env.local` — `supabase start` prints
them, and `supabase status -o env` prints them again later:

```env
NEXT_PUBLIC_SUPABASE_URL="http://127.0.0.1:54321"
NEXT_PUBLIC_SUPABASE_ANON_KEY="<anon key>"
SUPABASE_SERVICE_ROLE_KEY="<service role key>"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
```

Then:

```bash
npm run dev                    # http://localhost:3000
```

The ports are whatever `config.toml` assigns — this project does not
assume the default 54321 block. If `supabase status` reports a URL that
refuses connections, the running containers predate the current
`config.toml`; `supabase stop --project-id <id>` then `supabase start`
makes them agree again.

### Optional services

The feed renders without these, but the features that use them fail at
call time until they are set:

| Variable | Needed for |
| --- | --- |
| `GEMINI_API_KEY` | the whole pipeline — script, narration, slides |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_STRIPE_PRO_PRICE_ID` | subscriptions |
| `RESEND_API_KEY` | transactional email |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | web push |
| `CRON_SECRET` | authorises the daily dispatch route |
| `DEV_BYPASS_USER_ID` | local only — renders the feed without signing in |

One key now covers generation. There is no ElevenLabs account and no
Remotion Lambda deployment to stand up.

## How a lesson reaches a user

```text
cron (daily)
  └─ schedule-daily-video-generation
       ├─ fetch active professions
       └─ per profession: pick a topic, emit a generate event
            └─ microlearn-video-generation-pipeline
                 ├─ generate-script-gemini         scenes + palette
                 ├─ synthesize-audio-gemini-tts    .wav + word timings
                 ├─ generate-slides                one image per scene
                 ├─ ingest-assets-to-supabase      paths + slide manifest
                 └─ distribute-feed-deliveries  ──►  user_feed_deliveries
                                                          │
GET /  ── server component ── entitlements ───────────────┘
           │        │             │
           │        │             └─ locked → DailyDropLockedCard
           │        └─ signs every storage path
           └─ unlocked → FeedContainer → FeedScroller → VideoPlayerItem
                                                          │
                                        narration plays; slides cross-fade
                                        on cue points scaled to its length
```

Failures route to `handle-pipeline-failure`, which marks the video row
rather than leaving it stuck mid-generation.

## Provenance

The first 31 files here were written by the ADZ software factory: an orch2
technical architecture is decomposed into tickets, ordered by dependency,
and built by agents whose work is accepted or rejected by this repo's own
toolchain — `tsc`, `vitest`, `next build`, and a reachability check. No
agent's claim of success is trusted; exit codes decide.

That process has known blind spots, and this repo hit one worth recording.
Every gate passed while the app had no `src/app/page.tsx` at all: `/`
returned 404 and the entire feed UI was unreachable, because no ticket
owned the composition root. A compiler has no opinion about whether a
product has a home page. The reachability check that now catches this was
written in response, and the composition root was added by hand.

Two components — a plain `<video>` card and its action row — were deleted
rather than wired, because a second ticket had independently built a
fuller HLS player. Parallel agents paid for the same component twice.

A third blind spot showed up later and is worth recording too. A green
build says nothing about whether the repo *installs*: `npm ci` against the
committed lockfile failed on a missing `jose` entry, because the tree that
passed every gate had been built with `npm install` and the lockfile drift
was never committed. The factory grew a clean-install gate — clone HEAD to
a temp directory, `npm ci`, `npm run build` — in response. Use `npm ci`
here, not `npm install`, unless you are deliberately changing a dependency.

**Current state, verified:** typecheck clean, tests pass, every module
under `src/` is reachable from a real entry point, `npm ci` from a fresh
clone builds, and generation has been run end to end against a real
`GEMINI_API_KEY` — script, narration and slides — with the resulting
lesson playing in the feed.

**Not verified:** the shipped pipeline itself. That end-to-end run went
through `npm run seed:lesson`, which reimplements the same steps outside
Inngest rather than calling `src/app/api/inngest/route.ts`. The Inngest
functions, the daily cron, the Stripe webhooks and web push have not been
exercised against live services.
